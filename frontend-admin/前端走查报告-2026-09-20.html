P0-1

操作日志页存在请求风暴：每秒 2 次、永不停止

src/pages/AuditLogsPage.tsx:26-37（rangeToBounds）· :57-67（useAuditLogs 入参）· src/hooks/queries.ts:104-111（queryKey）

实测：进入「操作日志」页后，20 秒内发出 40 次 /api/v1/admin/audit-logs 请求（2.0 次/秒）， 且持续不衰减；45 秒后仍在继续。这是前端自造的请求循环，接上真实后端等于自我 DoS。 

// 现状：rangeToBounds 每次渲染都重新 new Date()，毫秒级时间戳每次都不同
const bounds = rangeToBounds(range)          // ← 每渲染一次就是新对象 + 新字符串
const logs = useAuditLogs({ ..., from: bounds.from, to: bounds.to })

// queryKey 直接吃下这个对象 → 每次渲染 key 都变 → 重新请求 → 触发渲染 → key 再变 …
queryKey: ['audit-logs', query, mode]

// 修法：时间边界只在 range 变化时算一次，且不要进 key
const bounds = useMemo(() => rangeToBounds(range), [range])
// 或者把 range 放进 queryKey，把 from/to 的换算搬进 queryFn
queryKey: ['audit-logs', { ...filters, range }, mode]
修复：用 useMemo([range]) 收敛时间边界；queryKey 里只放稳定的标量（range / page / 筛选值），不要在 key 里塞 new Date() 的产物。同页的 useReviews / useKnowledgeDocuments 都只传标量，所以没有这个毛病 —— 只有这一处踩了。

P0-3

顶栏账户头像的 <img> 没有尺寸约束，全站溢出遮挡

src/styles/admin.css:167-180 · src/app/AdminShell.tsx:122-124

.header-user .avatar 只把外层 <span> 约束成 30×30， 但 没有对应的 .header-user .avatar img 规则（表格里的 .cell-user .avatar img 有，顶栏这份漏了）。 结果 logo 按原始尺寸渲染：

  • 实测渲染盒 198×183，父容器只有 30×30；
  • 横向右边界到 1692px，越过 1600px 视口；

P0-4

知识治理的分类页签，实际筛的是「状态」字段

src/pages/KnowledgeGovernancePage.tsx:26-33（STATUS_TABS）· :53

页签文案是六个分类（全部规章 / 校制规 / 办事指南 / 奖助学金 / 后勤管理 / 教务教学）， 但 value 填的是六个状态码（all / ready / processing / failed / offline / archived）， 并原样传给了接口的 status 参数。文案与筛选维度完全对不上。

P1-2

顶栏全局检索：在知识治理页内发起时完全无反应

src/app/AdminShell.tsx:66-70 · KnowledgeGovernancePage.tsx:38

顶栏检索会把关键词塞进 query 串跳转 /knowledge-governance?query=…。 但页面里 keyword 只在首次挂载时读了 searchParams（useState(searchParams.get('query') ?? '')）， 没有监听 URL 变化。实测：已经在该页时输入「学籍管理」回车 → URL 变成 ?query=学籍管理， 但页面内搜索框仍是空、列表仍是全量 6 行 —— 用户看到的是「什么都没发生」。

修复：加一个把 searchParams.get('query') 同步进 keyword 的 useEffect。另外顶栏占位符写「检索用户、知识文档、审核记录…」，实际只会跳到知识治理页，建议收窄文案。
P1-3

三处筛选下拉是「死控件」（defaultValue 但无 onChange）

AuditLogsPage.tsx:184-193「动作行为特征」 · KnowledgeGovernancePage.tsx:211-226「版本状态」「解析状态」

这三处用 defaultValue="all" 且没有 onChange，可以选但选了不产生任何请求变化 —— 而同页其它下拉（操作者身份 / 业务模块 / 执行结果）都是正常接线的，所以这种「看起来能用其实不能用」的控件杀伤力更大。 另外同页还有「筛选」按钮（:227）也没有 onClick。

修复：接到已有的筛选状态上（审计页 action 维度已存在，只差绑定）；知识治理页的两个下拉要么接真实参数，要么先隐藏。
P1-4

内容审核的时间范围切换是死控件；审计日志的「自定义」没有日期选择

ContentAuditPage.tsx:139-147 · AuditLogsPage.tsx:26-37,151-160

P1-7

系统设置的表单草稿从不回填接口数据

SystemSettingsPage.tsx:38-53 · :78-99

security / rag 两份草稿都是写死的初始值，没有在 settings.data 到达时同步 （只有点「恢复默认设置」才会灌入）。后端一旦返回与写死值不同的配置，页面显示的就不是真实配置。

修复：加一个 useEffect(() => { if (settings.data && !dirty) resetDraft() }, [settings.data])，注意别覆盖用户正在编辑的草稿。顺带：「恢复默认设置」这个名字与实际行为（回滚到服务端最新值）不符，建议改成「放弃修改」。

≤ 900px 时侧栏直接消失，且没有替代导航

src/styles/admin.css:1427-1437

@media (max-width:900px) 里 .shell-rail { display:none }， 实测 768px 下可见导航项 0 个，顶栏检索也被隐藏 —— 除了右上角账户按钮（会跳到系统设置）， 用户没有任何换页手段。

P1-9

Drawer / Modal 没有焦点管理与滚动锁定

src/components/ui.tsx:178-275

  • 标了 aria-modal="true"，但打开后焦点仍留在背景，Tab 能跑到遮罩后面的顶栏和表格上（无 focus trap）；
  • 关闭后不把焦点还给触发元素；
  • 没有锁 body 滚动，抽屉里滚动会带动背景页面（scroll chaining）。
修复：打开时记录 document.activeElement、把焦点移入抽屉、body{overflow:hidden}，关闭时还原。ESC 关闭已经做了，这块补上就完整了。
P1-10

live 模式下操作日志页会一直卡在骨架屏

src/services/http.ts:13-17（timeout:30_000）· src/hooks/queries.ts:104-111（默认 retry 3）

前端对「后端不可用」的反馈太慢：axios timeout 30s × react-query 默认 retry 3， 加上 P0-1 的请求循环，实测 15 秒内页面始终是 6 行骨架、既不显示错误也不显示空态。 用户看到的是「一直在加载」，无法判断是慢还是挂了。

修复：查询默认 retry: 1、retryDelay 收紧，错误态尽快落到「后端未启动 / 请求失败」的 Notice（页面里已经有这个分支，只是等不到）。
